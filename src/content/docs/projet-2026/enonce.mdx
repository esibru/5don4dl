### Description de l'application à développer

Une entreprise faisant du développement logiciel de haut niveau (pensez à Google, Amazon, Apple, ...) souhaite vous engager pour mettre en place un système de documentation portant sur les diverses technologies utilisées par ses développeurs.

Cette documentation portera potentiellement sur tous les éléments utilisés par les développeurs dans leurs tâches quotidiennes. Voici quelques exemples:

- la façon d'utiliser une API développée par l'entreprise elle-même,
- des détails techniques propre à une partie d'un framework utilisé par les développeurs,
- les règles de bonnes pratiques générales que l'entreprise demande à ses développeurs de respecter,
- les règles de cybersécurité à respecter impérativement par les employés,
- etc.

L'entreprise souhaiterait disposer d'un système où:

1) Chaque employé de l'entreprise devra pouvoir se connecter au sein du système. Les employés n'ont pas tous les même droits. Certains pourront uniquement consulter un document technique, d'autres pourront aussi créer un tel document.

2) Deux documents puissent être mis en relation si les sujets traités sont jugés proches.
Par exemple: un document sur le framework Spring sera mis en relation avec les règles de bonnes pratiques applicables aux développeurs Java.

3) Le système doit permettre de voir les documents reliés à un document en cours de consultation et, si l'utilisateur le souhaite, passer à la lecture de ces documents facilement.

4) Une recherche de documents et d'utilisateurs doit évidemment être possible.

5) Les documents doivent être accessibles rapidement partout dans le monde. Le volet "performance" (retrouver rapidement un document) est donc à prendre en compte.

### Simplifications autorisées:

Dans le cadre de ce projet, le but est de démontrer votre compréhension des bases de données, et votre capacité à concevoir une architecture cohérente. 

Nous vous autorisons donc à apporter les simplifications suivantes:

1) Une interface utilisateur est évidemment nécessaire (pas d'application console). Nous vous autorisons cependant à simplifier celle-ci au maximum, du moment que toutes les contraintes fonctionnelles que nous vous imposons (voir ci-dessous) puissent être illustrées.

2) Le contenu des documents doit être stocké, d'une façon ou d'une autre. Vous êtes libre de fixer une limite supérieure sur la taille du contenu d'un article (exemple: 10 MB). Vous êtes également libre de simplifier le format de ce contenu (supposer que l'article ne contiendra que du texte, par exemple).

3) Vous êtes libre de simuler les données des documents et d'utiliser des données factices pour les utilisateurs.

### Contraintes fonctionnelles:

Attention: Ne pas respecter ces contraintes est synonyme d'échec à l'examen. Adressez-vous à votre enseignant si les consignes ci-dessous ne vous semblent pas claires.

Votre application doit permettre, au niveau:

**Des utilisateurs**: 

- encoder un nouvel utilisateur et afficher les données d'un utilisateur existant.

- gérer les niveaux de privilège d'un utilisateur donné. Les différents niveaux de privilèges implémentés sont laissés à votre appréciation, mais seront clairement précisés dans la documentation.

- afficher les documents écrit par un utilisateur donné.

**Des documents**:

- encoder un nouveau document et afficher le contenu d'un document existant.
- chaque document comprendra, au minimum: un titre et un contenu, un temps de lecture approximative, un auteur (qui sera toujours un utilisateur du système), ainsi qu'une liste (éventuellement vide) de documents reliés. 
- vous ne pouvez pas faire d'hypothèse à priori sur le nombre de documents qui seront liés à un document donné (ce nombre peut-être 0, mais peut aussi être très grand, ...).
- afficher un document (ainsi que les données reprises ci-dessus) donné.

**Des fonctionnalités de recherche**:

Il doit être possible de faire une recherche sur:

- les utilisateurs.
- les documents. 

Important: **Notre appréciation de votre travail sera notamment basé sur la variété des possibilités de recherche proposées.** (Exemple: recherche sur le titre d'un document, sur son contenu, sur le nom d'un utilisateur, etc.)


### Contraintes techniques:

Attention: Ne pas respecter ces contraintes est synonyme d'échec à l'examen. Adressez-vous à votre enseignant si les consignes ci-dessous ne vous semblent pas claires.

Votre application doit:

- utiliser plusieurs types de SGBD. Nous vous demandons au moins 3 SGBD distincts. Important: **utiliser un SGBD relationnel est permis**, et même encouragé lorsque c'est pertinent.
- répartir les données de façon cohérentes entre ces systèmes.
- comporter une interface utilisateur (pas d'application console). 
- présenter une découpe soignée du code, structurée en service métier cohérents. Tous vos services peuvent tourner dans un seul programme/processus, mais doivent être clairement séparés dans le code.

### Contraintes pédagogiques:

Attention: Ne pas respecter ces contraintes est synonyme d'échec à l'examen. Adressez-vous à votre enseignant si les consignes ci-dessous ne vous semblent pas claires.

- votre application sera accompagnée d'une documentation soignée, sous forme de slides. Ces slides seront utilisés lors de votre présentation pour votre examen oral. Présenter l'examen oral est obligatoire pour qu'une note vous soit attribuée.

- vous devez être capables de justifier et expliquer en détail non seulement le fonctionnement de l'application, mais aussi le code proposé et le fonctionnement des divers moteurs de base de données utilisés.

- vous devez également savoir justifier les SGBD choisis (relationnel, clé-valeur, orienté document, ...).
